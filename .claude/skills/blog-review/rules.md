# レビュー観点

観点ごとに「必須 / 提案 / 保留」のデフォルト重要度を書いてある。文脈で上下させてよい。
文体の正解は `.claude/rules/writing-style.md`。そこに書いてある「本人がよく使う表現」を直さないこと。

## 1. 機密情報・個人情報（必須）

ターミナルログをそのまま貼る書き方なので混入しやすい。以下を grep 相当で全文チェックする。

| 見るもの | パターン例 | 置き換え |
| --- | --- | --- |
| AWS アカウント ID | 12 桁の数字（`aws://123456789012`, `arn:aws:iam::123456789012:`） | `<account-id>` |
| IAM ユーザー名・ロール名 | `user/xxxx-prod-xxxx` | `<iam-user>` |
| アクセスキー・トークンの断片 | `****************ABCD`, `AKIA...`, `sk-...`, `ghp_...`, `xoxb-...` | 行ごと削除 |
| ローカルの絶対パス | `/Users/kwmt/...` | `~/...` または `<path>` |
| プロンプトのホスト名 | `[kwmt@MacBook-Pro]` | 行頭の `%` や `$` だけ残す |
| 個人特定できるサブドメイン・ID | `https://xxx.<name>.workers.dev`, KV namespace id, Version ID | `<name>`, `xxxxxxxx`（本人の既存表記） |
| 会社名・案件名 | 業務で触った固有名 | 「T社」「P社」（本人の既存表記） |
| メールアドレス・電話番号 | | 削除 |

- 伏せ字（`xxxxxxxx`, `<createしたid>`, `<path>`）になっていれば OK
- Play Store の自分のアプリ ID（`net.kwmt27.*`）、GitHub ID `kwmt`、ブログ URL、X の ID は公開情報なので指摘しない

## 2. front matter（必須）

- `date` の年月と `content/post/YYYY/MM/` が一致しているか。`2025/04/` に `date = "2024-04-19"` は間違い（実例あり）
- `title` が本文の内容と合っているか。他記事からコピーした front matter が残っていないか（`title = "2024年の目標"` のまま Chakra 移行メモになっていた実例あり）
- `categories` は 1 つで、既存の表記と一致しているか（`Flutter` と `flutter` の混在に注意）
- `tags` / `keywords` が本文と関係あるか。`keywords = ["Android", "Jetpack", "Compose","performance"]` が Next.js の記事に付いていたら指摘
- `draft` の値。公開前レビューなら `draft = true` のままかを確認して一言添える
- `slug = ""`, `author = "kwmt27"`, `toc = true` があるか

## 3. 誤字・誤変換（提案。ただし明らかな typo は必須）

本人の過去記事に実際にあった間違いのパターン。同種を重点的に探す。

- カタカナの音の抜け・入れ替え: クライント→クライアント、エミューレーター→エミュレーター、Inpsector→Inspector
- 英単語のつづり: `swtich`→`switch`, `targert`→`target`, `kotiln`→`kotlin`, `rembemr`→`remember`, `daialog`→`dialog`, `Mangaer`→`Manager`, `setttings`→`settings`, `Twe`→`Two`, `Lifecyle`→`Lifecycle`
- 同音の誤変換: 書き→下記、呼んで→読んで、最初期化→再初期化、起きたい→おきたい
- 打ち間違い: ななず→はず、こととが→ことが
- ひらがな表記（「まいかい」「めもっとく」「おねがいします」）は本人の癖なので指摘しない
- 助詞抜け・重複: 「パフォーマンス影響」→「パフォーマンスに影響」、「〜のを〜のを」
- 固有名詞の表記: `Golang`→`Go`, `Jetpack compose`→`Jetpack Compose`, `github`→`GitHub`, `cloudflare`→`Cloudflare`, `Nextjs`→`Next.js`, `typescript`→`TypeScript`, `Mac OS`→`macOS`, `AndroidStudio`→`Android Studio`
- ファイル名・URL の中の typo は URL が変わるので **必須** で指摘し、公開済みなら変えないよう注意書きする

## 4. リンク・画像（必須）

- `{{< figure src="/images/..." >}}` と `<img src="/images/..." />` は `static/images/...` にファイルがあるか
- `![](https://storage.googleapis.com/zenn-user-upload/...)` は Zenn 転載なので存在確認不要
- 過去記事へのリンク `/YYYY/MM/DD/slug/` は `content/post/YYYY/MM/slug.md` があり、その `date` の日が `DD` と一致するか
- 外部リンクは WebFetch で 404 / リダイレクトを確認（主要なものだけ）
- `[テキスト](URL)` の閉じ忘れ、URL に `)` や `。` が食い込んでいないか
- `{{< youtube ID >}}`, `{{< gist ID "file" >}}` の引数が空でないか

## 5. 構成（提案）

- `# はじめに` があるか（一覧・チートシート系の短い記事はなくてよい）
- 記事が途中で終わっていないか。「〜すると、」で終わる段落、ログの直後で本文が切れている（CDK 記事の実例）、`### 対策` が空、`TODO` が残っている
  - 途中で終わっているのを「メモとして公開する」のは本人の方針としてあり得るので、**保留** で「切れているように見える」と伝える
- 見出しレベルの飛び（`#` の次が `###`）
- 大見出しが `#` になっているか（`##` 始まりだと既存記事と揃わない。短いメモ記事は `##` 始まりの実例もあるので提案止まり）
- 同じ内容の重複段落（コピペで増えた段落）

## 6. 文章（提案）

- 主語と述語のねじれ: 「気になった変更点は、新しい機能が追加されました」型
- 一文が 150 文字を超えていて、かつ括弧の補足でないもの。本人の括弧補足付きの長文は指摘しない
- **同じ段落内**でのですます調と常体の混在。段落をまたぐ混在、コードブロック前の一行の体言止めは指摘しない
- 「〜することができます」が 1 記事に 3 回以上
- 同じ語尾が 3 文連続（「〜ます。〜ます。〜ます。」）。手順の羅列では気にしない
- 「が、」で 3 つ以上つながる文
- 指示語の指す先が不明（「これ」「それ」が直前の 2 つ以上を指し得る）
- 翻訳引用（`>` の英語 → `>` の日本語）の訳が原文とずれている

## 7. 表記（保留）

1 記事内での揃え方だけ見る。記事をまたいだ統一は求めない。

- 半角括弧 `()` と全角括弧 `（）` の混在
- 「、」「，」、「。」「．」
- 英数字の全角（`３つ`, `１年後`）。タイトル・見出しでは本人の癖として許容、本文の数値は半角
- 英単語と日本語の間の半角スペース有無（本人は入れない。入れる提案はしない）
- 「〜ですね」「〜ました！」などの感嘆・口語は指摘しない

## 8. コード（提案）

- コードブロックに言語指定があるか。つづりが正しいか
- 貼ったコードとその説明が一致しているか（`offset: Int` と書いて `Float` を渡している等）
- `+` / `-` の diff 表記が混在していないか（`diff` 言語指定があるとハイライトされる）
- インデントがタブとスペースで混ざっていないか
- 出力ログの中にプロンプト装飾（`╰─`, `─╯`）が残っている。本人はそのまま貼る派なので **保留**

## 9. らしさ（提案）

`.claude/rules/writing-style.md` の「本人が使わない表現」に該当する文があれば指摘する。AI で下書きした記事は特にここを見る。

- 「本記事では」「ご紹介します」「見ていきましょう」「ぜひ」「幸いです」「いかがでしたか」
- 「重要なポイントは以下の 3 つ」→ 箇条書き →「まとめ」で再掲
- 見出しの絵文字、コールアウト風の太字
- ダッシュ（—）
- 「筆者」「私たち」
- 「はじめに」で目的を宣言している（本人は動機から入る）
- 「おわりに」が本文の要約になっている（本人は感想と次にやることを書く）
- 「〜っぽい」「〜ようです」が、本人が確認していないことのごまかしに使われていないか（AI 下書きのときだけ疑う）

逆に、以下は **指摘しない**。

- 「〜っぽい」「〜かなと思います」「〜ようです」「〜らしい」「〜な気がします」
- 「しらんけど」「^^;」「...」「！」「？」の文中使用
- 括弧の長い補足
- 「ChatGPTに聞くと」「Claude に聞いたら」の出典
- 裸の URL
- 短い段落の連続、1 行だけの段落

## 10. Hugo 固有（必須）

- `{{<` と `>}}` の対応
- front matter の `+++` が 2 つ揃っているか、TOML として壊れていないか（`"` の閉じ忘れ、`,` 抜け、`=` 抜け）
- コードブロック内に `{{<` や `{{%` があるとショートコードとして解釈されて **ビルドが落ちる**。`{{</* ... */>}}` にエスケープ
- Hugo 0.111.3（CI）で使えない新しいショートコードや関数を使っていないか
