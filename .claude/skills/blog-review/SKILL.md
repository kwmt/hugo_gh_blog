# blog-review

対象の記事を読み、[rules.md](rules.md) の観点でレビューして、行番号付きの指摘を返す。
文体の判断基準は `.claude/rules/writing-style.md`、形式は `.claude/rules/post-format.md`（記事を Read すれば自動で読み込まれる。読み込まれていなければ先に Read する）。

## 手順

1. 対象を決める
   - `$ARGUMENTS` にパスがあればそれ。なければ `git status --short content/` で未コミット・変更中の記事を探す。複数あれば新しいものを対象にし、どれを見たか明記する
   - Zenn の URL や別ファイルのパスが渡されたら、その内容を対象にする。front matter と画像パスの観点は Hugo 用なので Zenn 記事には適用しない
2. 記事を最初から最後まで読む。front matter とディレクトリ（`content/post/YYYY/MM/`）を突き合わせる
3. rules.md の観点を上から順に確認する。**必須** の観点（機密情報・front matter・誤字・リンク切れ・Hugo 固有）は全文を機械的に見る
   - 画像は `static/images/...` にファイルがあるか `ls` で確認する
   - 過去記事へのリンク `/YYYY/MM/DD/slug/` は `content/post/YYYY/MM/slug.md` があるか確認する
   - 外部リンクは主要なものだけ WebFetch で到達を確認する。全部は見なくていい
4. 指摘を出力形式にまとめる。指摘がゼロの観点は書かない

## 出力形式

指摘は 3 段階に分け、それぞれ行番号順に並べる。

````markdown
## 必須（公開前に直す）

**L12** - 機密情報: AWS アカウント ID がログに残っている
```diff
- ⏳  Bootstrapping environment aws://123456789012/us-east-1...
+ ⏳  Bootstrapping environment aws://<account-id>/us-east-1...
```

## 提案（直したほうが読みやすい。本人判断）

**L40** - 誤字: 「クライント」→「クライアント」
```diff
- MCPクライント(Clineなど)
+ MCPクライアント(Clineなど)
```

## 保留（文脈依存。本人が決める）

**L88** - 構成: 「対策」の見出しが空のまま。書き忘れか、対策なしなら「対策なし」と一言あるとよさそう

## らしさチェック

本人が書いたように読める。「本記事では」が L3 にあるので削るとよい。
````

- 1 指摘 = 見出し 1 行 + diff。diff は修正前後をそのまま置き換えられる形で書く。diff にできない指摘（構成、空見出し）は 1 行の説明だけ
- 観点名は rules.md の見出しから取る（機密情報 / front matter / 誤字 / リンク / 構成 / 文章 / 表記 / コード / らしさ / Hugo）
- 最後の **らしさチェック** は 3 行以内。「本人が書いたように読めるか」「AI っぽい定型句が混ざっていないか」「削るべき一文があるか」

## やらないこと

- 口語（〜っぽい、〜かなと、しらんけど、^^;、...、！）や括弧の長い補足を「整える」提案はしない。これは本人の文体
- ですます調の記事の中でコードブロック前の一行が体言止めでも指摘しない
- 「〜と思います」を「〜です」に言い換える提案はしない
- 文章を要約・再構成する提案（「この段落は削れます」）は保留に 1 件までにする。構成は本人が決める
- 指摘のない観点について「問題ありません」と書かない。指摘だけを書く
- 記事本文を勝手に書き換えない。指摘に留める。「直して」と言われたら必須 → 提案の順に適用し、保留は触らない
